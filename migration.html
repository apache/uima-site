About the new website

This is a proposal for a new Apache UIMA website. It replaces the Anakia-based site that has been maintained in Subversion. This page explains what changed compared to the current site and lists the points that need a decision by the project. Please comment on the dev mailing list.

Open points for discussion

  1. PMC bylaws. The current site has a "Project Management Committee Bylaws" page from 2010. It required, among other things, a 3/4 majority of the votes cast (with at least three +1) to elect or remove PMC members and to create subprojects, and voting periods of 10 days (minimum 7). The project has in practice followed the common ASF conventions instead: votes are open for at least 72 hours and pass with at least three binding +1 votes and no −1. The new site drops the bylaws page and links to the ASF's How the ASF works and voting pages instead. Should the project record its actual practice somewhere, or rely on the ASF defaults?
  2. Project team. The current team list is outdated (it still names the incubator mentors). The new site links to the authoritative roster at projects.apache.org instead.
  3. Logo in the header. The header uses a one-colour version of the UIMA blocks that follows the light and dark theme, made from the official artwork in the ASF logo collection. The colour version is still available. This changes how the project mark appears and should be agreed on.
  4. Addons and sandbox. These are no longer featured on the home page or in the navigation, since most of the code is unmaintained. Their pages, such as Addons and Sandbox (current site), still exist at their old URLs. Should they be marked as retired, or removed?
  5. UIMA C++. Unchanged and still listed, pending a decision on its status.
  6. Publishing. The site would be built locally or by a GitHub Action and the result committed to an asf-site branch, as Apache Wicket does. The ASF's Jekyll builder is an alternative but cannot cache the manuals between builds and probably cannot build the search index. Where the new site's repository should live is also open.
  7. Which manual versions to keep. The site can build any number of versions per project; currently the latest two of the UIMA Java SDK and the latest of Ruta.

How the site is built

  • Jekyll instead of Anakia. Pages are HTML or Markdown with a little front matter. The site builds in a few seconds and can be previewed locally with rake serve.
  • Manuals from the release tags. Instead of copying built HTML into the site, the build fetches the AsciiDoc sources of each configured release tag and renders them in the site's design. Adding a release is one line in _data/docs.yml. Javadoc and the PDF editions remain release artifacts and stay where they are under /d/.
  • Search, light and dark mode. A self-hosted search index (Pagefind) covers the site and the current manuals. A switch in the header selects a light, dark or automatic theme.
  • ASF requirements. No external resources or trackers; the required ASF links and the trademark notices are in the footer.

What changed in the content

  • Home page: new introduction, a diagram of a pipeline and the CAS instead of the old picture, recent news (current site).
  • Documentation: one landing page for all manuals, with the version they were built from (current site).
  • Downloads: packages through the ASF mirror redirector; the Maven section now explains the uimaj-bom (current site).
  • Community: mailing lists, GitHub issue trackers and contributing in one page (current site: get involved, mailing lists). Jira, the wiki and SVN are no longer described; the CLA and contribution rules point to the ASF's own pages.
  • Ecosystem: the former "UIMA Resources on the Web", checked link by link. Dead projects were removed, active ones added.
  • Developer pages: replaced by the maintainer guide, which is part of the UIMA Java SDK documentation. Most old pages described the SVN era, for example doing a release and one-time setup on the current site.
  • Security: the footer links to the ASF security team; the project no longer keeps its own CVE list (current site).
  • News: all news items of the old site are kept as individual posts with an Atom feed (current site).
  • Other pages were converted automatically and keep their URLs; their text is unchanged. To compare one, open the same path on uima.apache.org.
