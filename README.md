# Apache UIMA website (prototype)

A Jekyll replacement for the Anakia-based site in `uima/site/trunk/uima-website`.

```sh
bundle install
rake build      # site into content/, manuals fetched and rendered on first run
rake search     # optional: Pagefind search index (needs Node)
rake serve      # http://localhost:4000
UIMA_DOCS=off rake serve   # skip the manuals while working on layout
```

## Manuals from release tags

The manuals are not copied in as built HTML. `_plugins/uima_docs.rb` reads
`_data/docs.yml` and, for every project and version listed there,

1. sparse-clones only the documentation folder of the release tag into `.cache/docs/src/`,
2. renders every top-level `*.adoc` file of that folder as one book with Asciidoctor,
   using the same attributes as the projects' Maven build, into the site layout,
3. publishes the books and their images below `/docs/<project>/<version>/`.

Rendered books are cached in `.cache/docs/render/` by commit, so a rebuild only
renders what changed. Adding a release is one line in `_data/docs.yml`; the first
version of a project is the current one, older ones get a notice and are left out
of the search index.

Cross-book links (`xref:ref.adoc#...`) work because all books of a version are
siblings. `link:api/...` is pointed at the published Javadoc, which the site does
not rebuild. The PDF editions remain release artifacts.

The generated `.htaccess` redirects `/d/<project>-current/<book>.html` to the new
location. Everything else below `/d/` and `/downloads/` (Javadoc, PDFs, old
manuals, slides) is not part of this repository and stays on the server as it is.

## Content

- Hand-written: `index.html`, `docs/`, `downloads.html` (from `_data/downloads.yml`),
  `news/`, `develop.html`, `search.html`.
- The diagram on the home page is `_includes/svg/uima-diagram.svg`, generated by
  `python3 _tools/make-diagram.py` (edit the script, not the SVG). Its colours come from
  CSS, so it follows the light and dark themes.
- Migrated: all other pages and `_posts/` were converted from `xdocs/` by
  `_tools/import-xdocs.rb` and keep their old URLs. They are ordinary pages now;
  edit them directly.

## Publishing

The site is built by a GitHub Action, not the ASF Jekyll builder, since the manuals
need git and plugins that it does not run. `.github/workflows/stage.yml` builds every
push to `new-site-v1` and commits the output in `content/` to the `asf-staging`
branch, which ASF infra serves at https://uima.staged.apache.org.
