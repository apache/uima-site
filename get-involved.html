Apache UIMA is developed in the open by volunteers. Questions, bug reports, documentation fixes and code are all welcome, and you don't need anyone's permission to start.

Mailing lists

The mailing lists are where the project discusses and decides things. To subscribe or unsubscribe, send an empty email to the address in the table; the links open your mail program with the address filled in.

The lists are public: everything you send, including your signature, is archived and can be found by search engines (see the ASF public archive policy). Please don't send attachments; link to them instead. More on how ASF mailing lists work.

Issues and pull requests

Each UIMA project tracks bugs and feature requests in the issue tracker of its GitHub repository, and takes contributions as pull requests there:

If you're not sure which project an issue belongs to, or want to discuss an idea before working on it, write to the dev list. Issues from before the move to GitHub are in the project's former Jira.

Contributing

Fork the repository, make your change and open a pull request. Small fixes need nothing more. For larger contributions we may ask you to sign the ASF's Individual Contributor License Agreement, and your employer the corporate one. The ASF's guide for contributors explains how Apache projects work and what to expect, and the code of conduct applies everywhere in the project.

The rules that apply to contributions are the ASF's own:

  • Contributor agreements: individual and corporate CLAs, and software grants for donating existing code
  • Third-party license policy: which licenses dependencies and included code may have
  • Generative tooling guidance: contributing code written with the help of AI tools
  • Source header policy: the license header every source file carries
  • IP clearance: the process for bringing a larger existing codebase into the project

For building and releasing UIMA see developing Apache UIMA.

Becoming a committer

People who contribute regularly over time are invited to become committers, with write access to the repositories, and later possibly to join the project management committee. There is no application process; invitations follow sustained contributions. The ASF describes this in becoming a committer.
